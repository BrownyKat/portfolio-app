The third week was about making the portfolio feel like a small design system. I broke the interface into atoms such as buttons and badges, then composed them into project cards, timelines, and navigation elements.

This made the code easier to reason about. A badge does one job. A card displays one project. Filtering happens separately from presentation. That structure follows the same principle I want the finished portfolio to communicate: organized, practical, and easy to extend.

## What I Practiced

- Building atomic UI without over-engineering.
- Keeping client-side interactivity isolated to the smallest component that needs it.
- Designing responsive grids that do not shift unexpectedly.

## Outcome

The activity gallery is now touch-ready, responsive, and driven entirely by the local project data.
